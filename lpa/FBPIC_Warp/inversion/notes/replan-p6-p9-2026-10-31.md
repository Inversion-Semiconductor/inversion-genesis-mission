# Re-plan of Phases P6 to P9 (Stage A), draft 2 of 2026-10-31

This draft updates Phases P6 to P9 with the measurements of M1 and M2 (plan Section 7, milestone item 3). Stage A stays E_L only, with K = 1. Decisions A and D change the plan text, and Section 4 lists the sections they change. Draft 1 was checked by three reviewers (facts, method, schedule); this draft applies their findings.

## 1. Measurements that change the plan

| # | Measurement (source) | Effect on P6 to P9 |
|---|---|---|
| 1 | Without EV, one tangent step costs 1.96x a primal step on Twin-S (12.7). The cost with EV is not measured; an EV run takes 88.8 s, against about 18 s without EV. | Use the Section 8 estimate (2 to 2.5 run-equivalents per gradient) until P7 step 3 measures it. Per dogbox iteration, AD needs about 2 run-equivalents and FD needs 3 (center and +-h), so AD is about 1.5x cheaper. |
| 2 | Twin-XS is chaotic at 3.85 cells per lambda0. FD resolves the derivative only up to N_t = 30, and AD matches FD there, with K(h) = 0 at h <= 1e-6 (12.7). | Twin-XS stays the strict short-horizon gate (N_t <= 30, small h). | 3 | Without EV, the Twin-S particle tangent grows by about 6e2 between steps 450 and 625, then stays near 1e6 per J up to step 1000. The field tangent still grows at step 1000. ## 2. Proposed phases

### P6. EV tangents (3.5 to 5.5 days)

0. Before any EV tangent, commit these changes:
   - the three deferred M1 fixes: the survival factor exp(-x5) in `ev_ionize`, an optional emission record, and a dirty marker on the target `git_hash`;
   - FD caches keyed by code hash (`runs/fd_<code_sha256[:12]>`), `ev_point` with size and target as arguments, and `runs/p3` marked read-only;
   - rule 8 cell-key sampling in `verify_param_gradient.py` (tracker IDs divisible by 256, records on the host), because full records do not fit in memory on Twin-S.
1. Implement the Section 5.3 tangents, the N-ion push tangent, and the reference VJPs. Run L1, including the separate E = 0 check and the emission copy as an index gather.
2. Add the EV tangents to `step`. Run L3 on a Twin-XS emission step.
3. Strict L4 gate: Twin-XS with EV and frozen emissions, N_t in {20, 28}, h in {1e-6, 1e-7, 1e-8}. First confirm that births occur by step 20.
4. Twin-S report: compute and store n_c (about 450), then run L4 with J_chk and frozen emissions at N_t in {n_c + 10, n_c + 50}, with h down to 1e-8 and sampled K(h). It is a gate only if an adjacent K = 0 pair exists, with e(h) following the h^2 trend.
5. Run the crossing probe (Section 6.3, rule 5).

Acceptance: steps 1 to 3 and 5 pass. Step 4 is reported.

### P7. Loss Jacobian, horizon sweep, and Jacobian usability (6 to 8 days)

1. Implement the residual objective `objective(state) -> (r_w, dr_w/ds)` over the 11 residuals, with alpha_D = 0 (decision A). Run L1 on every residual term, including the empty and nearly empty selections.
2. Run the synthetic K = 2 consistency check on Twin-XS at N_t <= 10. Set its tolerance from two repeated K = 1 runs, because deposit atomics differ between runs.
3. Measure memory and time per gradient on Twin-S with EV. Update Section 8.
4. Horizon sweep on Twin-S with J_chk at N_t in {1, 10, 50, n_c + 10, n_c + 50, n_c + 200, 1000, 2000}. Report e(h), sampled K(h), and the field and particle tangent growth up to step 2000. The loss is defined only where the selected beam has at least 1000 macroparticles, so run the loss part at N_t = 2000 only.
5. Jacobian usability on T0, at the full horizon:
   - Run `value_and_grad` at every point of three 41-point slices over +-0.05: around the T0 solution (E_L_hat of about 0.588), around the false minimum (about 0.545), and in the far field (0.75). Each run gives r and the AD column dr/dE_L.
   - Smoothed column: fit each of the 11 residuals on its slice. Also compute FD at h in {0.005, 0.01, 0.02, 0.05}.
   - Frozen-emission FD at small h at the same points. This separates code errors (AD against frozen FD) from the birth-time bias (frozen against free, Section 6.3 rule 4).
   - Report the distribution of the AD column error against the smoothed column (median, 90th percentile, cosine), and the dogbox fixed-point shift |(J_AD - J_smooth)^T r| / |J_AD^T J_smooth| at the T0 solution.
   - Cost: 123 gradient runs, about 6 to 8 h on one GPU.
6. Before the branch choice, run the epsilon = 0 gradient comparison on the reduced Twin-S (Section 5.5, item 4). If frozen against free dominates the error, the remedy is epsilon -> 0 or zero-weight creation, not a fallback to FD.

Acceptance: steps 1 and 2 pass. Steps 3 to 6 are reported. The user chooses the recovery branch with the step 5 and step 6 numbers (decision D):
- Branch 1, AD usable: the fixed-point shift is at most 0.005 (a quarter of the L6 tolerance). The full-horizon L4 is reported, not passed.
- Branch 1b, blend: J = a J_AD + (1 - a) J_smooth (literature note, Section 3.2 item 4).
- Branch 2, FD fallback: the FD Jacobian at h = 0.02. AD results are reported only.
- Branch 3, exploratory: as in Section 6.4.

### P8. Model checks (3 to 4 days)

Runs after M3, from the committed P6 code (decision C). Use `CUDA_VISIBLE_DEVICES` for every process: the stray GPU 0 context fix (`8f27245`) is not on this branch.

1. Birth count and memory on the full Twin-S at p_nz = 2 (the T1 setting), at epsilon in {1e-5, 1e-6, 0}. This decides the T1 configuration.
2. L5: write the CRN referee script, run the stochastic seeds for E_L (about 0.2 to 1.6 h at 22.5 s per production run), and compare with the EV secant and the AD gradient (Section 5.4 items 4 and 5).
3. The beam part of the epsilon sweep (Section 5.5, items 1 to 3), without MMD, on the reduced Twin-S.

Acceptance: as now. The T1 configuration is recorded before P9.

### P9. Stage A recovery (2 to 4 days)

1. `inversion/recover.py`: the 10-point design in E_L_hat, then dogbox from the 2 best design points that are at least 0.2 apart, plus the E_L_hat coordinates of the 5 starts of Section 3.4. Use the Jacobian of the chosen branch.
2. Generate T1 and T2.
3. Run L6 on T0′ (tight check with the L6 diagnostics), T0 (within 0.02), and T1 (offset reported as model bias). Report T2. Compare iterations, run-equivalents, wall time, and final error with the P3 FD recovery.

Acceptance: as now.

## 3. Milestones and effort

- M3 = P6 + P7: the gradient through ionization, the full-horizon sweep, and the Jacobian usability study. About 9.5 to 13.5 agent days. Main risk: P7 step 5.
- M4 = P8 + P9: model checks and the Stage A recovery. About 5 to 8 agent days.
- Stage A from today: about 14.5 to 21.5 agent days. The old plan had 13 to 20 days for P6 to P9. The increase pays for the cache refactor, the cell-key sampling, and the larger usability study.

## 4. Decisions for the user

- A. Stage A loss: keep the 11 whitened residuals with alpha_D = 0, and move MMD to Stage B or later. This changes Sections 2.4 ("alpha_D = 0 until Phase P7"), 2.6 item 3, P7 step 1, and 5.5 item 3. Recommended: the P9 recovery then uses the same loss as the P3 FD recovery.
- B. FD cache: key new caches by code hash and freeze `runs/p3` as evidence. Recommended: re-keying 311 runs would claim an equivalence that only L2t supports.
- C. Run P8 after M3 from committed code, not in parallel now. Recommended: P8 imports the EV code that P6 edits, and P8 needs only about 5 h of GPU time. A parallel run would need a pinned second worktree and a later merge.
- D. Recovery branch: change Section 6.4 and Section 2.5 item 5. The user still chooses the branch, now from the P7 step 5 and 6 numbers. The proposed bar for branch 1 is a fixed-point shift of at most 0.005 at the T0 solution, and the blend is added as branch 1b. Recommended: dogbox uses the residual Jacobian, so its fixed-point shift is the error that matters, not a scalar slope.
